<SectionTitle number="II"><T zh="订阅不含 API —— 自动化是另一条账" /></SectionTitle>

<T zh="想把 Kimi 接进脚本和系统, 订阅那点额度不算数; API 是另一套账户、另一条账单。" />

<T zh={<>这条线最容易踩。消费端会员和开放平台（platform.kimi.com）的 API 是两回事: 两套账户、两条计费, 会员买得再高也不附带 API 额度。<Footnote n={2} />API 按 token 计价（kimi-k3.1-pro 每百万 ¥13 输入 / ¥68 输出, 缓存命中 ¥1.3, K3 系列缓存写入另计）, base_url 是 <C>https://api.moonshot.cn/v1</C>, 支持 OpenAI Chat Completions / Responses 与 Anthropic Messages。第八章还讲过第三条账: 会员自带的 coding 端点（api.kimi.com/coding）—— 三套账户各算各的, 谁的 Key 也别串。</>} />

<T zh={<>我的判断很简单: 偶尔手动用 → 会员; 要稳定、批量、嵌进产品自动跑 → 走 API 单独算账。会员买的是给自己用, API 买的是让它替系统跑。订阅内额度不足但又不想升档时, 可以评估加油包; 它按实际用量付费, 与网页 Kimi 和 Kimi Code 共享同一余额, 仍不等于开放平台 API 充值。<Footnote n={4} /></>} />

<T zh={<>Kimi Code 本身仍随会员提供, 不是独立的 $19 / $39 商品。新套餐 Plus 起可用、旧套餐 Andante 起可用; 新套餐取消周限额, 旧套餐保留, 两者都有滚动 5 小时窗口与月度总池。<Footnote n={4} />所以选档时先报自己的新老套餐和实际限制, 比转述任何网传「独立订阅价格」都可靠。</>} />

<SectionTitle number="III"><T zh="我的取舍: 它的位置, 和什么时候别用它" /></SectionTitle>

<T zh="Kimi 不是永远「最便宜」, 也不是「样样第一」, 更不是谁的固定平替。把它只当平替, 你很容易拿它的短处比别人的长处。" />

<T zh={<>我看准它的独一份: 不是单项永远最强, 是<strong>一整套整合好的 agent 栈 + 国内可达 + 中文长材料顺手 + 开放权重路线</strong>叠在一起。现货要分清: K3 完整权重已经发布; K3.1 Pro 官方承诺 11 月 4 日前放出, 未上架前仍按承诺记。<Footnote n={3} /><Footnote n={5} />我选它, 是因为「聊天 + 交办 + 研究 + 写码」这一套对上了我的活, 还能国内直连。单拎一项去比, 它可能不占上风。</>} />

<T zh="我给一把按场景的尺子（只讲适配, 不踩同行）: 要一站式 agent 栈、中文长材料、国内顺手的编码 → 把 Kimi 列入首选; 最难的推理、最吃打磨的 agentic coding、不能错的输出 → 与其他前沿模型同题验收, 不预设固定赢家; 极致低价或开源自建 → 把 DeepSeek 等方案一起算部署与运维总账; 多模态创作、字节 / 阿里生态与企业合规 → 看现有生态里哪一家集成成本最低。" />

<T zh="我选主力的标准不是谁 benchmark 高, 是「最常干的那类活, 谁做得最顺」。多数人需要一两个主力加一个备胎, 不是五个都开着。价格随代际变化, 别把某一次涨价或降价写成永久品牌结论。" />
