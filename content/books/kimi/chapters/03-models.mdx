<SectionTitle number="I"><T zh="先认当前旗舰, 再看 K2 迁移线" /></SectionTitle>

<T zh={<>重活归 <strong>kimi-k3.1-pro</strong>: 3 万亿级参数、1M 上下文, 思考始终开启, <C>reasoning_effort</C> 可选 <C>low</C> / <C>high</C> / <C>max</C> —— 长链路编码、百万 token 长料、反复推的知识工作归它。高速版贵一倍输入输出价, 换约 2–3 倍输出速度。<Footnote n={1} /><Footnote n={3} /><strong>kimi-k3</strong> 是上一代旗舰: 2.8 万亿参数、1M 上下文, 仍有存在价值, 尤其是权重已经开放、需要自托管的场景。<Footnote n={2} /><Footnote n={5} /></>} />

<T zh={<>编码与预算线还有 <strong>kimi-k2.7-code</strong> 和 <strong>kimi-k2.6</strong>: 都是 256K 上下文, 前者强制思考、有高速变体, 后者思考可关、能走 Batch 六折。<Footnote n={2} /><Footnote n={4} /><Footnote n={6} />但这条线已经不是长期答案: K2 自 2026-10-31 起不再向新注册用户开放, 官方计划 12 月底全部下线; K2.5 已经在 8 月 31 日下线。现有工作流可以边用边迁移, 新系统别再绑死 K2 模型名。<Footnote n={2} /></>} />

<T zh="迁移期里, K2.6 的「简单活关思考」仍然可用, 最小写法如下:" />

<CodeBlock caption={<T zh="关掉思考的最小调用（仅适合仍在迁移期的 kimi-k2.6 工作流;K3.1 Pro 与 K2.7-Code 不能这样关)" />}>

```python
from openai import OpenAI

client = OpenAI(api_key="YOUR_KIMI_API_KEY",
                base_url="https://api.moonshot.cn/v1")

resp = client.chat.completions.create(
    model="kimi-k2.6",
    messages=[{"role": "user", "content": "把这段会议纪要按议题归类, 列出待办"}],
    extra_body={"thinking": {"type": "disabled"}},
)
print(resp.choices[0].message.content)
```

</CodeBlock>

<SectionTitle number="II"><T zh="我把四件典型活放上解剖台" /></SectionTitle>

<T zh={<>下面四个任务, 我把 token 画像全摆出来, 价格用开放平台标准价逐笔算。K3.1 Pro 每百万输入 ¥13 / 命中 ¥1.3 / 输出 ¥68; K3 为 ¥20 / ¥2 / ¥100; K2.7-Code 与 K2.6 输入 ¥6.5 / 输出 ¥27。<Footnote n={3} />为让算式可读, 以下暂不计 K3 系列另计的缓存写入费, 实账单要把它加回去。</>} />

<H3 id="task-pdf"><T zh="任务一 · 通读 300 页 PDF, 出一份结构化纪要" /></H3>

<T zh={<>画像: 300 页中文约 20 万 token 输入, 纪要约 3 千 token 输出, 一次过。<strong>K3.1 Pro: 13×0.2 + 68×0.003 ≈ ¥2.8</strong>（追问时前缀若命中缓存, 同口径约 ¥0.5）。<strong>K3 约 ¥4.3; K2.6 / K2.7-Code 约 ¥1.4</strong>。</>} />

<T zh={<>别急着选便宜的: 256K 的两颗塞 200K 材料后, 余量要留给提示词、工具输出和最终回答, 往往还是得分段 —— 分段丢的是「贯穿三百页的主线」这类全局判断。我的结论: <strong>10 万 token 以内且仍在迁移期, 可以先算 K2.6; 逼近或超过 20 万, K3.1 Pro 一次吃完更省心, 标价还低于 K3。</strong></>} />

<H3 id="task-coding"><T zh="任务二 · 编码 agent 跑一个跨 10 文件的功能改动" /></H3>

<T zh={<>画像: 20 轮迭代, 每轮平均 3 万 token 输入、2 千输出。合计输入 60 万（假设九成命中缓存, 即 54 万命中 + 6 万未命中）、输出 4 万。按百万 token 计: <strong>K3.1 Pro: 0.06×13 + 0.54×1.3 + 0.04×68 ≈ ¥4.2; K3 约 ¥6.3; K2.7-Code 约 ¥2.2</strong>。九成命中只是演算假设, 不是给你的缓存承诺。</>} />

<T zh={<>质量账不能拿旧榜硬凑。K3 在独立 DeepSWE 上是 69%±5%, K3.1 Pro 尚未被该榜收录; 官方虽然给出了更高的一代成绩, 但测试集和 harness 不同, 不能直接换算成「一次过的成本」。<Footnote n={1} /><Footnote n={7} /><strong>我的结论: 新增长链路任务先用 K3.1 Pro 做基线; 仍在 K2.7-Code 上的任务, 用同一件真活比较质量、返工和账单, 再决定何时迁。</strong>交互赶时间才考虑高速版, 后台批量别为速度多付钱。</>} />

<H3 id="task-batch"><T zh="任务三 · 一千条评论打标签(批量、可等)" /></H3>

<T zh={<>画像: 每条 500 输入 + 50 输出, 共 50 万输入、5 万输出, 走 Batch 六折（当前仅 K2.7-Code / K2.6）。<Footnote n={4} /><strong>K2.6 Batch: (6.5×0.5 + 27×0.05) × 0.6 ≈ ¥2.8, 单条不到 0.3 分钱。</strong>K3.1 Pro 不在 Batch 内, 标准价跑这批约 ¥9.9, 买的是这项机械活未必需要的旗舰推理。</>} />

<T zh={<>打标签这种「答错一眼能看出来」的活, 迁移期里用 K2.6 关思考确实便宜。但 Batch 当前只支持 K2 模型, 而 K2 已有下线时间表, 所以不要再把「永远 Batch + K2.6」当长期架构。<strong>短期按现有支持跑, 同步准备 K3.1 Pro 低推理档或普通实时接口的替代测算。</strong></>} />

<H3 id="task-chat"><T zh="任务四 · 日常问答与文档小修(高频、零碎)" /></H3>

<T zh={<>画像: 每次 2 千输入 + 5 百输出。按标准价粗算, K2.6 约 3 分钱, K3.1 Pro 约 6 分钱, 高频之后差价仍会积起来。<strong>我的结论: 简单、重复、容易验收的活先测低推理档; 只有答案质量连续几次不满意, 才升模型或升 effort。</strong>升档的触发器是「连续不满意」, 不是「万一这次难呢」。</>} />

<T zh={<>再看跑分 —— 先分两摞。<strong>第一摞, 厂商自评</strong>: K3.1 Pro 官方报 Terminal-Bench 4.0 为 65.7%, 略低于 Claude Opus 5.5 的 66.4%; 官方内部 Kimi Code Bench 3.0 Long-horizon 则从 K3 的 55.95% 提到 61.2%。这些数字值得看, 但测试条件与自有基准不能替你做独立验收。<Footnote n={1} /><strong>第二摞, 独立实测</strong>: DeepSWE（2026-09-22 更新, 统一 mini-SWE-agent harness）里 K3 是 69%±5%, 榜首多个模型为 74%; K3.1 Pro 尚未收录, 所以目前不能说它在这张榜上已经超过谁。<Footnote n={7} /></>} />
