<T zh="如果你完全不碰代码, 这章可以跳过 —— 这正是我把它单拎出来的原因。" />

<T zh={<>这一章我给开发者摆三道门: 一道是 <strong>Kimi Code</strong>, 跑在终端、对标 Claude Code 的第一方编码 agent; 一道是<strong>开放平台 API</strong> —— OpenAI Chat Completions / Responses 与 Anthropic Messages 三种兼容格式, 改几行配置就能把已经在用的 agent 接过来; 还有一道是可选的 <strong>CC-Switch</strong>, 把多套供应商配置收进一个面板。「国内可达 + 多协议 + 开放权重」这三样, 对国内开发者仍是少有的顺。</>} />

<SectionTitle number="I"><T zh="Kimi Code 是第一方的终端 agent" /></SectionTitle>

<T zh="它不是在聊天里贴代码, 是直接进你的仓库改 —— 读文件、跑命令、提改动。" />

<T zh={<>Kimi Code 是跑在终端里的命令行工具, 对标 Claude Code: 它在你的项目目录里直接读多个文件、跑命令、改文件, 一个完整的「改、跑、看、再改」循环, 不用你在浏览器和编辑器之间来回搬。<Footnote n={1} />模型列表现在是 K3.1 Pro（及高速版）、K3（及 256K 版）、K2.8 Preview 和 K2.7 Code Highspeed; 官方客户端用 <C>/model</C> 切换, 第三方工具要填对应模型 ID, 不要把显示名称当 ID。<Footnote n={18} /></>} />

<CodeBlock caption={<T zh="安装 Kimi Code CLI(macOS / Linux 二选一;Windows 用官方 PowerShell 脚本, 见文档)" />}>

```bash
# 官方脚本
curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash

# 或 npm(需 Node.js ≥ 22.19.0)
npm install -g @moonshot-ai/kimi-code

kimi --version   # 验证
```

</CodeBlock>

<T zh={<>装完用 <C>/login</C> 登录, 两条路任选: <strong>会员 OAuth</strong>(走你的 Kimi 会员订阅额度)或 <strong>开放平台 API Key</strong>(走按量计费)。<Footnote n={1} />会员那条的模型与上下文按档位解锁: 新套餐 Plus 起可用 K3.1 Pro / K3, Pro 起解锁高速版与 1M 上下文; 旧套餐对应 Moderato / Allegretto 门槛。新套餐取消 Code 周限额, 新旧套餐都有滚动 5 小时窗口并受月度共享池限制。<Footnote n={18} />要记牢的是: 会员 coding 端点(<C>api.kimi.com/coding</C>)与开放平台(<C>api.moonshot.cn</C>)是<strong>两个完全独立的账号体系, Key 互不通用</strong> —— 加上开放平台内部还分国内 / 国际两套, Kimi 一侧其实有三套账户, 配错哪一个都是 401。<Footnote n={2} /></>} />

<Callout kind="note" zh={<>Kimi Code 还能反向接别家: 它的 provider 配置支持 Anthropic Messages 协议, 你哪天想把同一个终端工具接到 Claude 上, 改配置即可。工具是中立的, 选模型是你的自由。</>} />

<Divider />

<SectionTitle number="II"><T zh="拿 Key 与三种协议格式(地基)" /></SectionTitle>

<T zh="所有接法都从同一块地基开始: 一个 Key、三种兼容格式。先把地基打对, 后面每个 agent 都只是填空。" />

<T zh={<>先去控制台建 Key: 国内在 <C>platform.kimi.com</C>(人民币, 微信 / 支付宝充值), 国际在 <C>platform.kimi.ai</C>(美元)。<strong>两套账户与 Key 完全独立, 混用直接 401</strong> —— 官方 FAQ 的原话是「不能混用」, 这也是接入失败最常见的原因。<Footnote n={3} /></>} />

<T zh={<>同一个 Key, 对应三种兼容格式。<strong>OpenAI Chat Completions</strong> 与 <strong>OpenAI Responses</strong> 共用国内 <C>https://api.moonshot.cn/v1</C>、国际 <C>https://api.moonshot.ai/v1</C>, 分别请求 <C>/chat/completions</C> 和 <C>/responses</C>; 鉴权都是 <C>Authorization: Bearer</C>, 官方惯用环境变量 <C>MOONSHOT_API_KEY</C>。<Footnote n={4} /><strong>Anthropic Messages</strong> 则用国内 <C>https://api.moonshot.cn/anthropic</C>、国际 <C>https://api.moonshot.ai/anthropic</C>。Codex 走原生 Responses, Claude Code 走 Anthropic, 都不需要协议转换。</>} />

<Tabs caption={<T zh="两套账户速查: Key 在哪建, 就用哪套端点(占位符 YOUR_KIMI_API_KEY 换成你的 Key)" />}>
<Tab label={<T zh="国内站(¥)" />}>

```bash
# 控制台: https://platform.kimi.com/console/api-keys
export MOONSHOT_API_KEY="YOUR_KIMI_API_KEY"
# OpenAI 兼容
export OPENAI_BASE_URL="https://api.moonshot.cn/v1"
# Anthropic 兼容(给 Claude Code 系用)
export ANTHROPIC_BASE_URL="https://api.moonshot.cn/anthropic"
```

</Tab>
<Tab label={<T zh="国际站($)" />}>

```bash
# 控制台: https://platform.kimi.ai/console/api-keys
export MOONSHOT_API_KEY="YOUR_KIMI_API_KEY"
# OpenAI 兼容
export OPENAI_BASE_URL="https://api.moonshot.ai/v1"
# Anthropic 兼容(给 Claude Code 系用)
export ANTHROPIC_BASE_URL="https://api.moonshot.ai/anthropic"
```

</Tab>
</Tabs>

<T zh={<>地基里还埋着一个限速坑: 速率按账户累计充值分档, 并发、RPM、TPM、TPD 与联网搜索 QPS 都可能成为瓶颈, 代金券不计入累计充值。别把旧教程里的某个 tier 数字当永久配置; 接入前看官方当前表格, 上线后在真实请求里处理 429 并做指数退避, SDK 自动重试也会消耗速率额度。<Footnote n={5} /></>} />

<Callout kind="warn" zh={<>接入报错先查这三样, 按命中率排: ① 国内 Key 配了国际端点(或反过来)→ 401; ② 拿会员订阅的 Key 去调开放平台(或反过来)→ 401; ③ tier0 限速 → 429。三样都不是配置写错了, 是账户对错了。</>} />

<SectionTitle number="III"><T zh="把 Key 配进你已经在用的 agent" /></SectionTitle>

<T zh="我按「官方文档写得有多明白」给它们排序, 每个附一份最小可用配置, 注意事项跟在配置后面。" />

<H3 id="claude-code"><T zh="Claude Code(Anthropic 兼容, 官方有指南)" /></H3>

<T zh={<>这是官方文档写得最全的一条: 把 <C>ANTHROPIC_BASE_URL</C> 指到 Kimi 的 Anthropic 兼容端点、用 <C>ANTHROPIC_AUTH_TOKEN</C> 鉴权, Claude Code 就把 Kimi 当后端。<Footnote n={6} />两个变量名别搞混 —— <C>ANTHROPIC_AUTH_TOKEN</C> 走 <C>Authorization: Bearer</C> 头, <C>ANTHROPIC_API_KEY</C> 走 <C>X-Api-Key</C> 头; 两者同时存在会冲突, 之前配过 <C>ANTHROPIC_API_KEY</C> 的先删掉。<Footnote n={7} />写进 <C>~/.claude/settings.json</C> 长期生效:</>} />

<CodeBlock caption={<T zh="~/.claude/settings.json —— 当前官方示例(国内站;国际站替换 BASE_URL 域名)" />}>

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.moonshot.cn/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "YOUR_KIMI_API_KEY",
    "ANTHROPIC_MODEL": "kimi-k3[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "kimi-k3[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "kimi-k3[1m]",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "kimi-k2.7-code",
    "ANTHROPIC_DEFAULT_FABLE_MODEL": "kimi-k3[1m]",
    "CLAUDE_CODE_SUBAGENT_MODEL": "kimi-k3[1m]",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "CLAUDE_CODE_EFFORT_LEVEL": "max"
  }
}
```

</CodeBlock>

<T zh={<>三条注意事项, 都来自当前官方指南: ① 各档模型变量要配全, 缺了对应场景(后台摘要、子 agent)会失败; ② <C>settings.json</C> 的 <C>env</C> 会覆盖 shell 同名变量, 修改后重启, 再用 <C>/status</C> 与 <C>/model</C> 核对; ③ 换用强制思考的 <C>kimi-k2.7-code</C> 时, 要在 Claude Code 里开启 Thinking, 否则请求被 400 拒绝。旧教程里的 <C>ENABLE_TOOL_SEARCH=false</C> 已不在当前最小配置中, 不要继续机械照抄。<Footnote n={6} /></>} />

<H3 id="opencode"><T zh="OpenCode(有内置 Moonshot, 最省事)" /></H3>

<T zh={<>OpenCode 内置了 Moonshot AI(国际)与 Moonshot AI (China)(中国区)两个供应商: 运行 <C>/connect</C> 选对应那个、粘贴 Key 即可, 不用手写配置。<Footnote n={10} />想自己管配置(比如团队共享), 就在 <C>opencode.json</C> 里声明一个 OpenAI 兼容供应商:</>} />

<CodeBlock caption={<T zh="opencode.json —— 自定义供应商(国内站;国际站换 baseURL 与内置供应商 Moonshot AI)" />}>

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "kimi": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Kimi (Moonshot CN)",
      "options": {
        "baseURL": "https://api.moonshot.cn/v1",
        "apiKey": "{env:MOONSHOT_API_KEY}"
      },
      "models": {
        "kimi-k3.1-pro": { "name": "Kimi K3.1 Pro", "limit": { "context": 1048576, "output": 131072 } },
        "kimi-k3": { "name": "Kimi K3", "limit": { "context": 1048576, "output": 65536 } }
      }
    }
  },
  "model": "kimi/kimi-k3.1-pro"
}
```

</CodeBlock>

<H3 id="codex"><T zh="Codex CLI(原生 Responses, 现在可以直连)" /></H3>

<T zh={<>旧结论是「Codex 只支持 Responses, Kimi 只有 Chat Completions, 所以要转换」。现在后半句已经变了: Kimi 原生提供 Responses API, 自定义 provider 的 <C>wire_api</C> 填 <C>responses</C> 即可直连 <C>kimi-k3.1-pro</C>, 不再需要 CC-Switch 或本地代理。<Footnote n={8} /><Footnote n={9} />先在终端设置 <C>KIMI_API_KEY</C>, 再写 <C>~/.codex/config.toml</C>:</>} />

<CodeBlock caption={<T zh="~/.codex/config.toml —— 开放平台国内站直连;国际站替换 base_url 域名" />}>

```toml
model = "kimi-k3.1-pro"
model_provider = "kimi"
model_context_window = 1048576

[model_providers.kimi]
name = "Kimi"
base_url = "https://api.moonshot.cn/v1"
env_key = "KIMI_API_KEY"
wire_api = "responses"
```

</CodeBlock>

<T zh={<>重启 Codex 后选一个真实仓库任务验证。若之前用 CC-Switch 接过, 先关闭它的 Codex 路由, 避免它继续改写配置或把 base_url 指回本地地址; 出现 <C>404 /v1/responses</C> 时, 先检查 base_url 是否恰好保留 <C>/v1</C>。<Footnote n={9} /></>} />

<H3 id="pi"><T zh="Pi(终端 agent, 配置文件驱动)" /></H3>

<T zh={<>Pi 是 Mario Zechner 写的终端编码 agent(仓库现为 earendil-works/pi, 原名 pi-mono), 全部供应商配置收在一个 <C>~/.pi/agent/models.json</C> 里。<Footnote n={11} />装好后把 Kimi 声明成一个 OpenAI 兼容供应商:</>} />

<CodeBlock caption={<T zh="~/.pi/agent/models.json —— apiKey 支持环境变量名 / 字面值 / !命令三种写法; 建议像下面这样填环境变量名, 别把 Key 本体写进文件" />}>

```json
{
  "providers": {
    "moonshot": {
      "baseUrl": "https://api.moonshot.cn/v1",
      "api": "openai-completions",
      "apiKey": "MOONSHOT_API_KEY",
      "models": [
        { "id": "kimi-k3", "name": "Kimi K3", "reasoning": true, "contextWindow": 1048576, "maxTokens": 65536 },
        { "id": "kimi-k2.7-code", "name": "Kimi K2.7 Code", "reasoning": true, "contextWindow": 262144, "maxTokens": 65536 }
      ]
    }
  }
}
```

</CodeBlock>

<T zh={<>保存后在会话里 <C>/model</C> 选择即可, 改配置不用重启。<Footnote n={11} />走会员订阅那条线的读者: Pi 还内置了 Kimi For Coding 供应商, 设环境变量 <C>KIMI_API_KEY</C> 就能用 —— 注意那套 Key 与开放平台互不通用, 别混。<Footnote n={2} /><Footnote n={11} /></>} />

<H3 id="cursor"><T zh="Cursor(原生 BYOK 与 Kimi Code 扩展是两条路)" /></H3>

<T zh={<>Cursor 原生自带 Key(BYOK)仍只支持 OpenAI / Anthropic / Google / Azure OpenAI / AWS Bedrock 五家, 自定义 Key 只覆盖标准聊天模型, Tab 补全继续走 Cursor 内置模型。<Footnote n={15} />但这不等于「Cursor 不能用 Kimi」: 官方另提供 Kimi Code for VS Code / Cursor 的 IDE 路径, 在扩展输入栏选择 Kimi 模型即可。想用 Cursor 原生 Agent 直连任意 Kimi 端点, 与在 Cursor 里使用 Kimi Code 扩展, 是两件不同的事, 别再混成一句「能」或「不能」。<Footnote n={19} /></>} />

<H3 id="webbridge"><T zh="顺带: 你的 agent 想动浏览器, 装 Kimi WebBridge" /></H3>

<T zh={<>配置再全, 上面这些 agent 也只会读写文件和跑命令 —— 碰不了网页。要让它像真人一样点按钮、填表单、跨站取数, 装一个 Kimi WebBridge: Chrome / Edge 扩展, 跑在你自己的浏览器里、直接继承你的登录态, 本地优先、数据不出设备, 扩展本身不收钱。<Footnote n={17} />Kimi Code、Claude Code、Cursor、Codex 这些本地 agent 都能挂; 装法是给 agent 发一句安装命令, 它自己把本地守护程序和技能装好。它解决的不是「模型接入」, 是「给 agent 一把手」。</>} />

<T zh={<>常有人问我: Kimi 配在哪个 agent 里表现最好? 我的排序是自己用出来的: 首推 <strong>Warp Agent</strong> —— 它支持自定义 API 服务商端点, 把第二节那个 OpenAI 兼容端点填进去就能用, 效果非常好; 其次是 <strong>Kimi Code</strong> 自己 —— 模型稳定性最好, 长跑几乎不中断。</>} />

<SectionTitle number="IV"><T zh="CC-Switch: 可选的配置面板, 不再是必经桥" /></SectionTitle>

<T zh={<>当你只有一套配置, 手动改 env 就够了; 当你在 Kimi、Claude 官方和其他模型之间频繁切换, CC-Switch 这类第三方面板可以少做一些重复劳动。<Footnote n={16} />但要更新一个旧认知: Codex 已能走 Kimi 原生 Responses API, CC-Switch 的协议转换不再是必需品。它的价值回到「集中管理配置」, 而不是「没有它就接不上」。macOS 仍可这样安装:</>} />

<CodeBlock caption={<T zh="安装 CC-Switch(macOS;Windows / Linux 在 ccswitch.io 下安装包)" />}>

```bash
brew install --cask cc-switch
```

</CodeBlock>

<T zh={<>它会维护供应商 profile, 并把启用中的配置写入对应工具的配置文件。代价是「谁在改配置」多了一层: 如果手动直连与面板路由同时开着, 后写入的一方可能覆盖前一方。Claude Code 改完用 <C>/status</C> 核, Codex 改完检查 <C>config.toml</C> 的 base_url 和实际启动模型; 旧 Codex 路由不用了就关掉。<Footnote n={6} /><Footnote n={9} /><Footnote n={16} /></>} />

<Callout kind="note" zh={<>两句实话。一, CC-Switch 是社区第三方工具, 不是 Kimi 官方维护, 预设值可能与官方当前推荐不同。二, 只有启用它的本地路由时, Key 和请求才需要经过那层转换; 公司环境应先做安全评估。能原生直连时, 少一层代理通常也意味着少一类排错变量。</>} />

<T zh={<>和手动改 env 怎么选? 一套配置走天下 → 手动就够, 第二、三节都给了。多套之间频繁切、或要给团队演示 → 再评估 CC-Switch。别为了使用一个配置面板, 反过来把已经能直连的链路重新绕回代理。</>} />

<T zh="我划三条边界。完全不写代码 → 跳过这章, 用 Agent 模式做表、做站就够。会写、但只改一两行 → 对话框里贴代码更快, 不必请出终端。值得请出终端 agent: 多文件、长链条、要反复跑测试的改动 —— 投入越重, 终端循环越划算。" />

<T zh={<>还有一类藏得更深的甜区: <strong>不像代码的文件工作</strong>。我自己前两天的一次: 给这本书做宣传物料 —— 我把需求说清, 它写了 HTML 海报母版、用 Playwright 逐张渲染成图, 又把两小时的直播回放按时间线剪成 59 秒的竖版短片（ffmpeg 切片、压字幕、拼首尾卡）。全程我没打开过设计软件或剪辑软件, 只做了两件事: 说清楚要什么, 和验收。海报、视频、批量处理素材 —— 产出是文件、过程可复算的活, 都归它。很多人用了半年, 都没想起来它能干这个。</>} />
